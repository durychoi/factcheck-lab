# 팩트체크 분석 화면

Tavily로 근거를 모으고, 그 근거만으로 Gemini가 판정합니다. 탭 3개로 나뉩니다.

| 탭 | 용도 | 비용 |
|---|---|---|
| 문장 분석 | 주장 한 문장을 6단계로 판정 | Tavily 1~2회, Gemini 1회 |
| 핵심 주장 | 기사에서 주장 최대 5개를 골라 6단계로 판정 | 주장당 Tavily 1~2회, Gemini 1회 |
| 출고 전 점검 | 기사 전체의 사실 항목을 전수 점검(4단계) | 15,000자 기준 Gemini 약 45~85회, Tavily 약 40~160회(추정) |

## 여는 방법
배포 주소 https://durychoi.github.io/factcheck-lab/ 를 엽니다. 로컬에서는 `index.html`을 더블클릭합니다.

## 사용
상단에 Tavily 키와 Gemini 키를 입력합니다(이 브라우저의 localStorage에만 저장).

### 문장 분석
주장 한 문장을 입력하고 [분석]을 누릅니다.

### 핵심 주장
1. 기사 링크를 넣고 [본문 가져오기]를 누르면 Tavily Extract로 본문을 가져와 원문 입력칸에 채웁니다. 유료·차단 기사는 직접 붙여 넣으세요.
   메뉴·광고 문구가 섞일 수 있으니 확인·수정한 뒤 [주장 추출]을 누릅니다(최대 15,000자). **기사 전문이 Google(Gemini)로 전송됩니다.**
   - 좌담·인터뷰처럼 줄 맨 앞에 `이름:` 또는 `이름 직함:` 표시가 2번 이상 있으면 주장에 화자가 붙습니다(예: `김영익 소장: …`). 검색·판정에는 화자를 뺀 주장 내용만 보냅니다.
2. 추출된 주장에서 최대 5개를 고릅니다. 각 주장에는 원문 문장 번호와 원래 문장이 함께 나옵니다. 주장 문구는 검증 전에 고칠 수 있습니다.
   - 발언이 든 문장은 [발언 사실](누가 실제로 말했는가)과 [발언 내용](말한 내용이 사실인가)으로 나뉩니다.
   - 숫자·날짜·금액이 든 주장에는 판정과 관계없이 "원자료 확인 필요"가 붙습니다.
3. 예상 사용량을 확인하고 [검증 시작]을 누릅니다. 주장은 4초 간격으로 하나씩 검증됩니다. [중지]를 누르면 진행 중인 주장까지만 마칩니다.
4. 결과 표의 행을 누르면 이유와 근거 목록이 펼쳐집니다.

### 출고 전 점검
1. 기사 링크로 본문을 가져오거나 직접 붙여 넣습니다. **기사 제목** 칸의 제목·링크와 같은 기사와 그 사본(포털 전재 등)은 근거에서 뺍니다(순환 검증 방지).
2. [사실 항목 추출]: 약 3,000자 구간마다 Gemini 1회로 사실 항목(수치 / 날짜 / 인물·직함 / 기관·명칭 / 사건 / 인용)을 뽑습니다. 원문 표현이 문장에 글자 그대로 있어야 받습니다.
3. 점검할 유형을 고르면(빠른 선택: 전체 / 수치·날짜만 / 인물·직함만) 예상 사용량과 소요 시간이 나옵니다.
4. [점검 시작]: 같은 주제의 문장끼리 묶어 묶음마다 Tavily 검색(basic) 1회(근거 부족 시 2회) + Gemini 1회로 항목을 각각 판정합니다. 4초 간격 순차 실행.
   - 한도 초과·키 오류로 멈추면 끝난 결과는 남고, [남은 항목 점검]으로 이어서 할 수 있습니다.
5. 결과 표: 문장 / 원문 표현 / 유형 / 판정 / 근거상 값 / 근거 번호. 필터(전체·불일치·근사·확인 불가·미점검)와 CSV 내려받기(엑셀용)가 있습니다.
   - 판정: 일치 / 근사(반올림·표기 차이) / 불일치 / 확인 불가
   - "원자료 확인 필요": 확인 불가이거나 근거가 [백과]·[기타]뿐인 항목. 확인 불가 항목에는 1차 확인처(KRX, 한국은행 ECOS, KOSIS, 국가법령정보센터 등)를 안내합니다.

## 시험
코드를 고치기 전과 후에 반드시 돌립니다(Node.js 필요).

```
node tests/run.js
```

- `tests/*.test.js`가 판정 보정·근거 선정·문장 나누기·화자·전수 점검 로직을 확인합니다.
- 버그를 보고받으면 그 사례를 먼저 시험에 넣어 실패를 확인한 뒤 고칩니다.
- 시험 데이터의 URL은 `test.invalid`, 인물·기관은 "가상" 이름을 씁니다.

## GitHub Pages
저장소에 이 폴더를 올리고 Settings → Pages에서 브랜치를 지정하면 됩니다. 키는 코드에 없으므로 함께 올라가지 않습니다.

## 설계 원칙
- 판정은 Tavily 근거 목록만으로 수행(temperature 0).
- 출처 URL은 Gemini 응답이 아니라 Tavily 근거 목록에서 번호로 찾아 붙임. 목록에 없는 번호는 버림.
- 근거 0건 또는 유효 근거 번호가 없으면 "판단 유보".
- 검색은 `advanced`. 우선 출처(정부·법원·통계청·학술·언론)로 1차 검색하고, 5건 미만이면 전체 검색으로 채움.
- 출처 유형([공공기관] [학술] [언론] [백과] [기타])은 `sources.js`의 도메인 표로 코드가 분류. 매체를 추가하려면 이 파일만 수정.
- 판정에 쓴 근거가 모두 [기타]이면 "판단 유보" 외 판정을 내지 않음(Gemini 지시 + 코드 강제).
- 미래 예측·전망, 가정, 의견은 근거가 있어도 "판단 유보"(주장 유형을 먼저 분류, 코드 강제).
- "거짓" 계열은 반박하는 사실 근거, "사실" 계열은 지지하는 사실 근거가 있어야 함. 지지 근거가 없다는 것만으로는 거짓이 아님.
- 화면의 근거 번호는 Gemini에 전달한 번호와 같음. 이유 문장에서 인용한 근거는 모두 "판정에 사용"으로 표시. 목록에 없는 번호는 [번호 오류].
- 판정 보정 로직은 `judge.js`, 근거 선정은 `evidence.js`.
- 기사 분석: 문장 번호와 원문은 코드가 나눈 문장 목록에서만 가져옴(Gemini가 세지 않음). 목록에 없는 문장 번호는 버림. 순수 로직은 `article.js`, 화면은 `article-ui.js`.
- 한도 초과(429)·키 오류가 나면 남은 주장 검증을 멈추고 끝난 결과는 유지.
- Tavily는 오류 응답(401·429 등)에 CORS 헤더를 붙이지 않아 브라우저에서는 연결 실패로만 보임. 그래서 Tavily 연결 실패는 "키·한도·네트워크 확인" 안내와 함께 치명 오류로 처리.
- 화자는 코드가 판별(`article.js`의 `SPEAKER_LINE`, 제외 목록 `NON_SPEAKER_LABELS`). `Q:`/`A:` 형식은 판별하지 않음.
- 출고 전 점검: 근사·불일치는 근거상 값이 인용한 근거의 제목·요약에 글자 그대로 있어야 인정(아니면 확인 불가). 근거가 없다는 것만으로는 불일치가 아님.
- 인물·직함 항목의 검색어에는 직함을 넣지 않고 이름·소속 기관만 씀(확증 편향 방지). 코드에서도 `items.js`의 `stripTitles`로 제거: 직함은 낱말 전체가 `TITLE_WORDS`와 같을 때만, 접미사 일치는 `COMPOUND_TITLES`(선임연구원·리서치센터장 등)만. 기관·매체명(○○연구원, 이코노미스트)은 남김.
- 1차 확인처는 `items.js`의 `PRIMARY_SOURCES` 표(주제 키워드 → 기관). API 호출은 하지 않음.
- 출고 전 점검 로직은 `items.js`, 화면은 `precheck-ui.js`.
- JS·CSS 수정 후에는 `index.html`의 `?v=` 값을 바꿔야 브라우저가 새 파일을 불러옴.
